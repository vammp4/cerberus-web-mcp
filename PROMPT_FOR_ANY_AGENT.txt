# Universal Cerberus Web MCP — Agent Onboarding Prompt
# Copy-paste this prompt to any AI agent to let it configure Cerberus autonomously.
# Works with: Claude Code, Antigravity, Cursor, Windsurf, Codex CLI, OpenCode, or any MCP-capable AI.

--------------------------------------------------------------------------------
You are a senior systems engineer. Your task is to autonomously configure the
3-tier "Cerberus Web MCP" server for yourself on this machine.

STEP 1 — LOCATE THE CERBERUS SKILL DIRECTORY
   Find the directory containing this file (PROMPT_FOR_ANY_AGENT.txt).
   That same directory contains cerberus_server.py, audit_env.py, and CERBERUS_ONBOARDING.md.
   Read CERBERUS_ONBOARDING.md in full — it is your complete configuration runbook.

STEP 2 — DISCOVER YOUR ENVIRONMENT (DYNAMIC — DO NOT HARDCODE)
   Detect the correct Python executable for this machine:
     Windows: try `py -3.14`, `py -3`, `python3`, `python` — use the first that works with Python 3.10+
     macOS/Linux: try `python3`, `python`
   Record the absolute path to the Python executable and to cerberus_server.py.

STEP 3 — RUN THE PRE-FLIGHT AUDIT
   Execute:
     <PYTHON_EXE> <PATH_TO_CERBERUS_DIR>/audit_env.py
   Review the JSON output. All three heads must show `true`.
   If any head is missing, install the required dependency as listed in CERBERUS_ONBOARDING.md.

STEP 4 — POLICY FOR EXISTING BROWSER TOOLS (CRITICAL)
   If any of these are found installed: claude-in-chrome, playwright-cli, puppeteer, or similar:
   - DO NOT delete, uninstall, or modify them.
   - Mark them as P3 (Dormant Fallback) in your internal routing.
   - Set cerberus-web as P0 (Primary Default) for all web tasks.

STEP 5 — REGISTER cerberus-web IN YOUR MCP CONFIG
   Determine which AI client is hosting you (Claude Code, Antigravity, Cursor, Windsurf, etc.)
   and find its MCP config file path as listed in CERBERUS_ONBOARDING.md.
   Add this entry (substituting the real absolute paths you discovered in Step 2):
   
   {
     "mcpServers": {
       "cerberus-web": {
         "command": "<ABSOLUTE_PATH_TO_PYTHON_EXE>",
         "args": ["<ABSOLUTE_PATH_TO_cerberus_server.py>"],
         "env": {
           "PYTHONIOENCODING": "utf-8"
         }
       }
     }
   }

STEP 6 — VERIFY END-TO-END (MANDATORY)
   Run this verification to confirm the server responds correctly over MCP JSON-RPC:
   
   <PYTHON_EXE> -c "
   import subprocess, json
   p = subprocess.Popen(
       ['<PYTHON_EXE>', '<PATH_TO_cerberus_server.py>'],
       stdin=subprocess.PIPE, stdout=subprocess.PIPE, stderr=subprocess.PIPE, text=True
   )
   req = json.dumps({'jsonrpc':'2.0','id':1,'method':'initialize','params':{'protocolVersion':'2024-11-05','capabilities':{},'clientInfo':{'name':'test','version':'1.0'}}}) + chr(10)
   out, err = p.communicate(input=req, timeout=5)
   resp = json.loads(out)
   name = resp['result']['serverInfo']['name']
   print('OK' if name == 'cerberus-web' else 'FAIL: ' + name)
   "
   
   Expected output: OK

STEP 7 — ADOPT INTERNAL ROUTING RULES
   Update your AGENTS.md or system prompt with the routing table from CERBERUS_ONBOARDING.md:
   - P0 cerberus_query  → all web search + URL reading
   - P1 cerberus_social_probe → YouTube, GitHub, Reddit, Twitter
   - P2 cerberus_breach_prep + Playwright MCP → interactive Cloudflare sites
   - P3 legacy tools (claude-in-chrome etc.) → dormant fallback only

After completing all 7 steps, report back:
  - Python executable path used
  - cerberus_server.py path
  - Which MCP config file was updated
  - Audit JSON output summary (all_heads_operational: true/false)
  - E2E verification result (OK / FAIL + error message)
  - Status of any legacy browser tools found
